## Теоретическое обоснование

В объектно-ориентированном программировании классы взаимодействуют друг с другом. Существует три основных типа отношений:

| Отношение      | Характер связи                                | Пример              |
| :------------- | :-------------------------------------------- | :------------------ |
| **Ассоциация** | «использует», «знает о»                       | Врач → Пациент      |
| **Агрегация**  | «состоит из» (часть может жить без целого)    | Автомобиль → Колёса |
| **Композиция** | «состоит из» (часть не может жить без целого) | Дом → Комнаты       |

**Агрегация** - это отношение «часть-целое», при котором «части» могут существовать независимо от «целого» и могут принадлежать разным «целым». В C++ реализуется через указатели или ссылки. Класс-«целое» не отвечает за удаление объектов-«частей».

**Композиция** - это отношение «часть–целое», при котором «части» не могут существовать без «целого». Целое полностью контролирует время жизни частей. Реализуется через поля-объекты, `std::unique_ptr` или ручное выделение/освобождение памяти (`new`/`delete`).

**Статические члены класса** - принадлежат не отдельному объекту, а всему классу в целом. Существуют в единственном экземпляре. Используются для подсчета объектов (счётчики), хранения общих настроек или реализации паттерна Singleton.

**Паттерн «Одиночка» (Singleton)** - порождающий паттерн проектирования, который гарантирует, что у класса есть только один экземпляр, и предоставляет глобальную точку доступа к нему. Конструктор делается приватным, а копирование запрещается.



## Выполнение индивидуального задания


Класс Route описывает сущность маршрута и хранит его номер, а также начальную и конечную точки. Данный класс не зависит от других сущностей и может существовать самостоятельно. Листинг класса Route представлен ниже:

```cpp

class Route
{
private:
	string routeNumber;
	string startPoint;
	string endPoint;

public:
	Route(const string &num, const string &start, const string &end) : routeNumber(num), startPoint(start), endPoint(end)
	{
		cout << "[Создан] маршрут №" << routeNumber << " (" << startPoint << ' - ' << endPoint << ")" << endl;
	}

	~Route()
	{
		cout << "[Удалён] маршрут №" << routeNumber << endl;
	};

	string getInfo() const
	{
		return "№" + routeNumber + " (" + startPoint + " - " + endPoint + ")";
	}
};


```


Класс Bus представляет собой автобус, который агрегирует в себе маршрут. Связь с классом Route реализована через указатель, что позволяет автобусу не отвечать за время жизни маршрута. В классе также реализовано статическое поле busCount для подсчета общего количества созданных автобусов и проверка на nullptr. Код класса Bus приведен ниже:

```cpp

class Bus
{
private:
	string model;
	string licensePlate;
	Route *route; // Указатель на маршрут (Агрегация)

	static int busCount;

public:
	Bus(const string &mod, const string &plate, Route *r = nullptr)
		: model(mod), licensePlate(plate), route(r)
	{
		busCount++;
		cout << "[Создан] Автобус: " << model << " [" << licensePlate << "]" << endl;
	}

	~Bus()
	{
		busCount--;
		cout << "[Удален] Автобус: " << model << " [" << licensePlate << "]" << endl;
	}

	// Сеттер для смены маршрута
	void setRoute(Route *r)
	{
		route = r;
	}

	void print() const
	{
		cout << "Автобус: " << model << " [" << licensePlate << "], ";
		// Проверка на nullptr
		if (route != nullptr)
		{
			cout << "назначен на маршрут " << route->getInfo() << endl;
		}
		else
		{
			cout << "не имеет маршрута" << endl;
		}
	}

	// Статический метод для получения количества автобусов
	static int getBusCount()
	{
		return busCount;
	}
};

int Bus::busCount = 0;

```


Класс Depot реализует паттерн проектирования «Одиночка» (Singleton), гарантируя наличие только одного экземпляра депо в системе. Для этого конструктор скрыт в секции private, а доступ осуществляется через статический метод getInstance(). Внутри класса также реализована агрегация автобусов через вектор указателей. Листинг класса Depot показан ниже:

```cpp

class Depot
{
private:
	string name;
	vector<Bus *> buses;

	Depot(const string &n) : name(n)
	{
		cout << "Депо открыто: " << name << endl;
	}

	static Depot *instance;

public:
	// Запрет копирования
	Depot(const Depot &) = delete;
	Depot &operator=(const Depot &) = delete;

	// Статический метод получения экземпляра
	static Depot *getInstance(const string &n = "Городское депо")
	{
		if (instance == nullptr)
		{
			instance = new Depot(n);
		}
		return instance;
	}

	void addBus(Bus *bus)
	{
		// Проверка на nullptr
		if (bus != nullptr)
		{
			buses.push_back(bus);
			cout << "Автобус добавлен в депо \"" << name << "\"" << endl;
		}
	}

	void print() const
	{
		cout << "\n--- Депо \"" << name << "\" содержит " << buses.size() << " автобус(ов) ---" << endl;
		if (buses.empty())
		{
			cout << "Депо пусто." << endl;
		}
		else
		{
			for (const auto &bus : buses)
			{
				bus->print();
			}
		}
		cout << "--------------------------------------------------\n"
			 << endl;
	}

	~Depot()
	{
		cout << "Закрыто депо: " << name << " (Автобусы не удаляются - агрегация)" << endl;
	}
};

Depot *Depot::instance = nullptr;
```




Функция main() демонстрирует работу созданной архитектуры. В ней последовательно создаются объекты маршрутов и автобусов, проверяется работа паттерна Singleton (сравниваются адреса двух вызовов getInstance()), а также тестируется граничный случай с добавлением пустого указателя (nullptr) в депо. Код функции main() представлен ниже:


```cpp
int main()
{
	setlocale(LC_ALL, "ru");

	cout << "1. Создаем маршруты независимо от автобусов:" << endl;
	Route route1("101", "Центр", "Север");
	Route route2("205", "Центр", "Юг");
	cout << endl;

	cout << "2. Создаем автобусы:" << endl;
	Bus bus1("ЛиАЗ-5292", "А123ВС", &route1);
	Bus bus2("Волгабас", "В456ЕК", &route2);
	Bus bus3("ПАЗ-3205", "С789МН");

	cout << "Всего создано автобусов: " << Bus::getBusCount() << endl
		 << endl;

	cout << "3. Демонстрация паттерна Singleton:" << endl;
	Depot *depot1 = Depot::getInstance("Центральное");
	Depot *depot2 = Depot::getInstance("Запасное");

	if (depot1 == depot2)
	{
		cout << "-> Успех: depot1 и depot2 указывают на один и тот же объект!" << endl;
	}
	cout << endl;

	cout << "4. Добавляем автобусы в депо:" << endl;
	depot1->addBus(&bus1);
	depot1->addBus(&bus2);
	depot1->addBus(&bus3);
	depot1->print();

	cout << "5. Проверка граничных случаев:" << endl;
	depot1->addBus(nullptr);
	cout << endl;

	cout << "6. Завершение программы:" << endl;

	return 0;
}
```

## Ответы на контрольные вопросы

1. **Что такое композиция? Приведите пример.** 
   Композиция - это отношение «часть-целое», при котором части не могут существовать без целого. Целое управляет жизненным циклом частей. Пример: Дом и Комнаты. Если дом сносят, комнаты перестают существовать.
   
2. **Что такое агрегация? Чем она отличается от композиции?** 
   Агрегация - это более слабое отношение «часть-целое», при котором части могут существовать независимо от целого. Отличие в том, что при агрегации целое **не** отвечает за создание и уничтожение частей (они передаются извне). Пример: Библиотека и Книги. Если библиотека закрывается, книги не исчезают.
   
3. **Как реализовать композицию в С++? Приведите пример кода.**
   Через поля-объекты, умные указатели (`std::unique_ptr`) или ручное управление памятью (`new`/`delete` в конструкторе/деструкторе).
   ```cpp
   class Engine {};
   class Car {
       Engine engine; // Поле-объект (композиция)
   };
   ```
   
4. **Как реализовать агрегацию в С++? Приведите пример кода.**
   Через сырые указатели, ссылки или `std::shared_ptr` (если нужно разделяемое владение), при этом класс-контейнер не удаляет объекты в своем деструкторе.
   ```cpp
   class Book {};
   class Library {
       std::vector<Book*> books; // Указатели (агрегация)
   };
   ```
   
5. **В чём разница между временем жизни частей при композиции и агрегации?**
   При композиции время жизни части строго ограничено временем жизни целого (часть умирает вместе с целым). При агрегации часть может жить дольше целого или быть общей для нескольких целых.
   
6. **Что такое статическое поле класса? Чем оно отличается от обычного поля?**
   Это переменная, принадлежащая самому классу, а не его объектам. Оно существует в единственном экземпляре для всех объектов класса, в отличие от обычных полей, которые создаются для каждого экземпляра отдельно.
   
7. **Как объявить и определить статическое поле? Где оно хранится?**
   Объявляется в классе со словом `static`. Определяется (выделяется память) вне класса. Хранится в статической области памяти (сегмент данных), а не в куче или стеке.
   
8. **Что такое статический метод? Можно ли из него обратиться к нестатическим полям?**
   Это метод, принадлежащий классу, который можно вызывать без создания объекта. Из него **нельзя** напрямую обратиться к нестатическим полям, так как статический метод не привязан к конкретному экземпляру (`this` отсутствует).
   
9. **Для чего используются статические счётчики объектов?**
   Для отслеживания количества созданных или живых в данный момент объектов определенного класса (как в примере с `Bus::busCount`).
   
10. **Что такое паттерн «Одиночка» (Singleton)? Для чего он нужен?**
    Это паттерн, гарантирующий наличие единственного экземпляра класса и предоставляющий глобальную точку доступа к нему. Нужен для управления общими ресурсами (база данных, логгер, настройки, депо в данной работе).
    
11. **Как запретить создание копий объекта (конструктор копирования)?**
    Удалить конструктор копирования и оператор присваивания копированием с помощью `= delete;` (стандарт C++11).
    
12. **В каком порядке вызываются конструкторы и деструкторы при композиции?**
    Конструкторы вызываются в порядке: сначала создаются части (поля-объекты), затем выполняется тело конструктора целого. Деструкторы вызываются в обратном порядке: сначала тело деструктора целого, затем уничтожаются части.
    
13. **Можно ли изменить статическое поле из обычного метода?**
    Да, можно, так как обычный метод имеет доступ к статическим полям класса.
    
14. **Почему статические поля нужно определять вне класса?**
    Объявление внутри класса лишь сообщает компилятору о существовании переменной. Определение вне класса выделяет для нее физическую память.
    
15. **В каких случаях стоит использовать композицию, а в каких - агрегацию?**
    Композицию - когда объекты-части являются неотъемлемой частью целого и не имеют смысла вне его (Дом и Комнаты). Агрегацию — когда объекты существуют самостоятельно и могут подключаться к разным целым (Студент и Университет, Автобус и Депо).
