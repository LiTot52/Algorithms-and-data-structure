## Теоретическое обоснование

**Динамический массив (Vector)** - это структура данных, которая хранит элементы в непрерывной области памяти (в куче), но, в отличие от статического массива, может изменять свой размер во время выполнения программы.

Основные компоненты класса:
* `T* data` - указатель на динамический массив.
* `int sz` - текущий размер (количество элементов).
* `int cap` - ёмкость (выделенная память).

**Стратегия удвоения ёмкости:** при добавлении элемента, если `sz >= cap`, память перевыделяется с увеличением ёмкости в 2 раза. Это обеспечивает амортизированную сложность `O(1)` для операции `push_back`, так как дорогие операции перевыделения (стоимостью `O(n)`) происходят всё реже и реже.

**Амортизированный анализ `push_back`.** Расширение происходит при размерах 1, 2, 4, 8, ... Каждое расширение копирует столько элементов, каков текущий размер:

| Вставка             | Копирований |
| ------------------- | ----------- |
| 1                   | 0           |
| 2 (расширение 1→2)  | 1           |
| 3 (расширение 2→4)  | 2           |
| 5 (расширение 4→8)  | 4           |
| 9 (расширение 8→16) | 8           |

При `n` вставках всего копирований не более 1 + 2 + 4 + ... + n ≈ 2n. Вместе с `n` записями получается около 3n элементарных операций на `n` вставок, то есть `O(n)` на всю серию и `O(1)` в среднем на одну вставку. Для сравнения: при росте ёмкости на фиксированное число `k` копирований было бы порядка `n²/(2k)`, то есть `O(n²)`.

Практическое подтверждение: в программе ёмкость при последовательных `push_back` растёт как `1, 2, 4, 4, 8, 8, 8, 8, 16, 16`.

**Правило трёх и пяти:**
* *Правило трёх* гласит, что если классу нужен собственный деструктор, конструктор копирования или оператор присваивания, то, скорее всего, нужны все три.
* *Правило пяти* добавляет к ним конструктор перемещения и оператор присваивания перемещением (семантика перемещения позволяет избежать глубокого копирования и повысить производительность).

**Итераторы** - это объекты, которые позволяют перебирать элементы контейнера. В простейшем случае (как в Vector) итератором может выступать обычный указатель (`T*`). Для константных итераторов (`const_iterator`) используются указатели на константу (`const T*`), которые запрещают изменение элементов.

## Листинг программы

### vector.hpp

```cpp
#pragma once
// #include <iostream>
#include <stdexcept>
#include <utility>
// #include <algorithm>

template <typename T>
class Vector
{
private:
	T *data; // Указатель на динамический массив
	int sz;	 // кол-во элементов в векторе
	int cap; // кол-во элементов выделено в память

public:
	using iterator = T *;
	using const_iterator = const T *;

	iterator begin()
	{
		return data;
	}

	iterator end()
	{
		return data + sz;
	}

	const_iterator begin() const
	{
		return data;
	}

	const_iterator end() const
	{
		return data + sz;
	}

	Vector() : data(nullptr), sz(0), cap(0) {};

	~Vector()
	{
		delete[] data;
	}

	int size() const
	{
		return sz;
	}

	int capacity() const
	{
		return cap;
	}

	bool empty() const
	{
		return sz == 0;
	}

	void reserve(int newCap)
	{

		if (newCap <= cap)
		{
			return;
		}

		T *newData = new T[newCap];

		for (int i = 0; i < sz; i++)
		{
			newData[i] = data[i];
		}
		delete[] data;
		data = newData;
		cap = newCap;
	};

	void push_back(const T &value)
	{
		if (sz >= cap)
		{
			int newCap = (cap == 0) ? 1 : cap * 2;
			reserve(newCap);
		}
		data[sz] = value;
		sz++;
	};

	void pop_back()
	{
		if (empty())
		{
			throw std::underflow_error("Вектор пуст");
		}
		sz--;
	}

	T &operator[](int index)
	{
		if (index < 0 || index >= sz)
		{
			throw std::out_of_range("Индекс вне диапазона");
		}
		return data[index];
	}

	const T &operator[](int index) const
	{
		if (index < 0 || index >= sz)
		{
			throw std::out_of_range("Индекс вне диапазона");
		}
		return data[index];
	}

	void clear()
	{
		sz = 0;
	}

	//! Конструктор копирования
	Vector(const Vector &other) : data(nullptr), sz(other.sz), cap(other.cap)
	{
		data = new T[cap];
		for (int i = 0; i < sz; i++)
		{
			data[i] = other.data[i];
		}
	};

	//! SWAP
	void swap(Vector &other)
	{
		std::swap(data, other.data);
		std::swap(sz, other.sz);
		std::swap(cap, other.cap);
	}

	//! Копирующий operator
	Vector &operator=(const Vector &other)
	{
		if (this != &other)
		{
			Vector temp(other);
			swap(temp);
		}
		return *this;
	}

	//! Конструктор перемещения
	Vector(Vector &&other) noexcept
	{
		data = other.data;
		sz = other.sz;
		cap = other.cap;

		other.data = nullptr;
		other.sz = 0;
		other.cap = 0;
	}

	//! Перемещающий operator
	Vector &operator=(Vector &&other) noexcept
	{
		if (this != &other)
		{
			delete[] data;
			data = other.data;
			sz = other.sz;
			cap = other.cap;

			other.data = nullptr;
			other.sz = 0;
			other.cap = 0;
		}
		return *this;
	}

	// !REVERSE
	void reverse()
	{
		for (int i = 0; i < sz / 2; i++)
		{
			std::swap(data[i], data[sz - 1 - i]);
		}
	}

	explicit Vector(int n) : data(nullptr), sz(0), cap(0)
	{
		if (n < 0)
			throw std::invalid_argument("Аргумент не может быть отрицательным");
		if (n == 0)
			return;
		data = new T[n];
		for (int i = 0; i < n; i++)
			data[i] = T();
		sz = n;
		cap = n;
	}
};

```

### main.cpp

```cpp

#include <iostream>
#include <stdexcept>
#include <utility>
#include "vector.hpp"

void printVector(const Vector<int> &v, const char *name)
{
	std::cout << name << " (size=" << v.size() << ", cap=" << v.capacity() << "): ";
	for (Vector<int>::const_iterator it = v.begin(); it != v.end(); ++it)
		std::cout << *it << " ";
	std::cout << std::endl;
}

int main()
{
	// Конструктор по умолчанию, size, capacity, empty
	std::cout << "=== 1. Default constructor ===" << std::endl;
	Vector<int> v;
	std::cout << "size=" << v.size() << " cap=" << v.capacity()
			  << " empty=" << v.empty() << std::endl;

	// push_back и стратегия удвоения ёмкости
	std::cout << "\n=== 2. push_back (capacity doubling) ===" << std::endl;
	for (int i = 1; i <= 10; i++)
	{
		v.push_back(i);
		std::cout << "size=" << v.size() << " cap=" << v.capacity() << std::endl;
	}

	// operator[]
	std::cout << "\n=== 3. operator[] ===" << std::endl;
	std::cout << "v[5] = " << v[5] << std::endl;
	v[5] = 99;
	std::cout << "after v[5] = 99: v[5] = " << v[5] << std::endl;

	// pop_back
	std::cout << "\n=== 4. pop_back ===" << std::endl;
	v.pop_back();
	printVector(v, "v");

	// Итераторы и range-based for
	std::cout << "\n=== 5. iterator / range-based for ===" << std::endl;
	for (int x : v)
		std::cout << x << " ";
	std::cout << std::endl;

	for (Vector<int>::iterator it = v.begin(); it != v.end(); ++it)
		*it *= 2;
	printVector(v, "v after *2");

	// const_iterator
	std::cout << "\n=== 6. const_iterator ===" << std::endl;
	const Vector<int> &cv = v;
	for (Vector<int>::const_iterator it = cv.begin(); it != cv.end(); ++it)
		std::cout << *it << " ";
	std::cout << std::endl;
	std::cout << "const operator[]: cv[0] = " << cv[0] << std::endl;

	// reverse
	std::cout << "\n=== 7. reverse ===" << std::endl;
	printVector(v, "before");
	v.reverse();
	printVector(v, "after ");

	// Конструктор копирования
	std::cout << "\n=== 8. Copy constructor ===" << std::endl;
	Vector<int> a;
	for (int i = 1; i <= 3; i++)
		a.push_back(i);
	Vector<int> b = a;
	b[0] = 100;
	printVector(a, "a");
	printVector(b, "b (a[0] must stay 1)");

	// Оператор присваивания копированием + самоприсваивание
	std::cout << "\n=== 9. Copy assignment ===" << std::endl;
	Vector<int> c;
	c = a;
	c.push_back(4);
	printVector(a, "a");
	printVector(c, "c");
	a = a;
	printVector(a, "a after a = a");

	// Конструктор и оператор перемещения
	std::cout << "\n=== 10. Move constructor / move assignment ===" << std::endl;
	Vector<int> d = std::move(a);
	std::cout << "a.size()=" << a.size() << " d.size()=" << d.size() << std::endl;
	Vector<int> e;
	e = std::move(d);
	std::cout << "d.size()=" << d.size() << " e.size()=" << e.size() << std::endl;
	printVector(e, "e");

	// clear
	std::cout << "\n=== 11. clear ===" << std::endl;
	e.clear();
	std::cout << "empty=" << e.empty() << " size=" << e.size()
			  << " cap=" << e.capacity() << std::endl;

	// Конструктор с размером
	std::cout << "\n=== 12. Vector(int n) ===" << std::endl;
	Vector<int> s(5);
	printVector(s, "s");

	// Исключения
	std::cout << "\n=== 13. Exceptions ===" << std::endl;
	try
	{
		int x = s[10];
		std::cout << x << std::endl;
	}
	catch (const std::out_of_range &ex)
	{
		std::cout << "out_of_range: " << ex.what() << std::endl;
	}

	try
	{
		Vector<int> empty;
		empty.pop_back();
	}
	catch (const std::underflow_error &ex)
	{
		std::cout << "underflow_error: " << ex.what() << std::endl;
	}

	try
	{
		Vector<int> bad(-1);
	}
	catch (const std::invalid_argument &ex)
	{
		std::cout << "invalid_argument: " << ex.what() << std::endl;
	}

	return 0;
};
```

## Ответы на контрольные вопросы

**1. Почему динамический массив называется «динамическим»?**
Потому что его размер не фиксируется на этапе компиляции (в отличие от статических массивов) и может изменяться во время выполнения программы. Память для него выделяется в куче (heap), и при необходимости программа может запросить дополнительный блок памяти, скопировать туда старые данные и продолжить работу.

**2. Что такое ёмкость (capacity) и чем она отличается от размера (size)?**
* **Размер (`size`)** - это количество элементов, которые фактически хранятся в массиве в данный момент.
* **Ёмкость (`capacity`)** - это количество элементов, под которые уже выделена память.

Ёмкость всегда больше или равна размеру. Разница между ними позволяет добавлять новые элементы без немедленного перевыделения памяти (и дорогостоящего копирования), пока `size` не достигнет `capacity`.

**3. Почему при расширении массива ёмкость удваивается, а не увеличивается на фиксированное число?**
Если увеличивать ёмкость на фиксированное число (например, на 1), то при каждой вставке, требующей расширения, придётся копировать все `n` элементов. В итоге для `n` вставок потребуется `O(n²)` операций. Удвоение ёмкости гарантирует, что перевыделение памяти будет происходить всё реже (через 1, 2, 4, 8, 16... элементов), что обеспечивает амортизированную сложность `O(1)` для вставки.

**4. Какова амортизированная сложность операции push_back? Почему?**
Амортизированная сложность - **O(1)**. Хотя отдельная операция при перевыделении памяти (когда `size == capacity`) стоит `O(n)`, эти дорогие операции происходят экспоненциально редко. Суммарное время выполнения `n` операций `push_back` составляет `O(n)`. Если разделить это время на количество операций, получается `O(1)` на одну вставку.

**5. Что такое «правило трёх»? Когда оно применяется?**
«Правило трёх» гласит: если классу требуется определить хотя бы один из трёх методов - **деструктор, конструктор копирования или оператор присваивания копированием** - то, скорее всего, ему нужны все три. Оно применяется в классах, которые управляют ресурсами (например, динамической памятью), чтобы избежать утечек памяти и двойного освобождения (double free) при копировании.

**6. Что такое «правило пяти»? Чем оно отличается от «правила трёх»?**
«Правило пяти» расширяет правило трёх, добавляя **конструктор перемещения** и **оператор присваивания перемещением**. Оно актуально начиная с C++11. Отличие в том, что оно позволяет реализовать семантику перемещения, которая оптимизирует работу с временными объектами, избегая ненужного глубокого копирования.

**7. В чём разница между конструктором копирования и оператором присваивания?**
* **Конструктор копирования** создаёт **новый** объект как копию существующего (вызывается при инициализации, например `Vector b = a;`).
* **Оператор присваивания** вызывается для **уже существующего** объекта, заменяя его текущее содержимое данными из другого объекта (например `c = a;`). Старые ресурсы объекта при этом нужно освободить: в нашей реализации это делает идиома copy-and-swap, так как старая память после `swap` оказывается во временном объекте `temp` и освобождается его деструктором.

**8. Зачем нужна проверка `if (this != &other)` в операторе присваивания?**
Это защита от **самоприсваивания** (например, `v = v;`). Если реализовать присваивание через освобождение старой памяти (`delete[] data`) и последующее копирование из `other`, то при самоприсваивании мы сначала уничтожим собственные данные, а затем попытаемся копировать их из уже удалённой памяти, что приведёт к неопределённому поведению. В перемещающем операторе без проверки мы бы удалили `data`, а затем забрали бы тот же самый (уже удалённый) указатель. Проверка также избавляет от лишней работы при `v = v`.

**9. Что такое итератор? Как он связан с указателем?**
Итератор - это объект, который позволяет перебирать элементы контейнера, не раскрывая его внутреннюю структуру. В простейших контейнерах, таких как `Vector`, итератор реализуется как обычный указатель (`T*`), так как элементы хранятся в непрерывном блоке памяти. Указатель поддерживает все необходимые операции: разыменование, инкремент, декремент и сравнение.

**10. Зачем нужны методы begin() и end()?**
Они возвращают итераторы на первый элемент и на элемент, следующий за последним (полуинтервал `[begin, end)`). Эти методы задают стандартный диапазон, который используется алгоритмами STL (например, `std::sort`, `std::find`) и конструкцией `range-based for`.

**11. Как реализовать range-based for для своего контейнера?**
Для этого достаточно реализовать в классе методы `begin()` и `end()`, возвращающие итераторы (или указатели), а также их константные версии (`begin() const` и `end() const`). Компилятор автоматически развернёт цикл `for (auto x : v)` в обычный цикл с использованием этих методов.

**12. Что такое «глубокое копирование»? Чем оно отличается от «поверхностного»?**
* **Поверхностное копирование** копирует только значения полей класса. Если среди них есть указатель, то копируется сам адрес, и два объекта начинают указывать на одну и ту же область памяти (что приведёт к двойному удалению).
* **Глубокое копирование** выделяет новую область памяти и поэлементно копирует туда данные. После этого объекты полностью независимы друг от друга.

**13. Что такое семантика перемещения и зачем она нужна?**
Это механизм (появившийся в C++11), который позволяет «забирать» ресурсы (например, указатель на массив) у временного объекта (rvalue) вместо их дорогостоящего копирования. Это значительно повышает производительность, так как позволяет избежать лишних выделений памяти и копирования больших объёмов данных. После перемещения исходный объект остаётся в пустом, но корректном состоянии.

**14. Почему конструктор перемещения помечается `noexcept`?**
Пометка `noexcept` гарантирует, что конструктор перемещения не выбросит исключение. Это критически важно для стандартных контейнеров (например, `std::vector`). При перевыделении памяти вектор использует перемещение для старых элементов только в том случае, если конструктор перемещения помечен как `noexcept`. В противном случае он вынужден использовать более медленное копирование для обеспечения строгой гарантии безопасности исключений.

**15. Как правильно освобождать память в деструкторе?**
Поскольку память в `Vector` выделялась с помощью оператора `new T[capacity]`, освобождать её нужно с помощью оператора `delete[] data;`. Использование `delete data;` (без квадратных скобок) приведёт к неопределённому поведению: для массива будет вызван деструктор только для одного элемента, а освобождение памяти выполнится некорректно. Вызов `delete[]` для `nullptr` безопасен, поэтому дополнительная проверка не нужна.
