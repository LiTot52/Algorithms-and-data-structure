## Теоретическое обоснование

**Анализ сложности** - математический способ оценки эффективности алгоритма в зависимости от размера входных данных. Различают два вида сложности:

- **временная** - сколько времени выполняется алгоритм;
- **пространственная** - сколько памяти он использует.

**О-нотация (Big O)** описывает асимптотическое поведение функции при стремлении аргумента к бесконечности. Говорят, что `f(n) = O(g(n))`, если существуют положительные константы `c` и `n₀` такие, что `0 ≤ f(n) ≤ c · g(n)` для всех `n ≥ n₀`. На практике это означает, что при оценке отбрасываются константы и младшие члены: `2n² + 100n + 1000` → `O(n²)`.

Основные классы сложности:

| Сложность  | Название                | Пример                           |
| :--------- | :---------------------- | :------------------------------- |
| O(1)       | Константная             | Доступ по индексу в массиве      |
| O(log n)   | Логарифмическая         | Бинарный поиск                   |
| O(n)       | Линейная                | Линейный поиск, сумма элементов  |
| O(n log n) | Линейно-логарифмическая | Быстрая сортировка, слиянием     |
| O(n²)      | Квадратичная            | Пузырьковая сортировка           |
| O(2ⁿ)      | Экспоненциальная        | Рекурсивное вычисление Фибоначчи |
| O(n!)      | Факториальная           | Генерация всех перестановок      |

**Амортизированный анализ** оценивает среднюю стоимость операции в серии вызовов. Например, `push` в динамическом массиве иногда стоит O(n) (при расширении), но в среднем по серии операций - O(1).

**Шаблоны функций и классов** позволяют писать один код, работающий с разными типами данных. Тип подставляется компилятором на этапе компиляции:

```cpp
template <typename T>
class Stack { /* ... */ };

Stack<int> a;
Stack<string> b;
```

**Двусвязный список (List)** - линейная структура данных, состоящая из узлов, каждый из которых хранит значение и указатели на предыдущий и следующий узлы. Список хранит указатели на первый и последний узлы, поэтому добавление и удаление на концах выполняются за O(1) без сдвига элементов, а доступ к элементу по индексу требует последовательного прохода - O(n). В стандартной библиотеке аналогом является `std::list`.

**Экспериментальный анализ** - измерение реального времени работы с помощью `std::chrono`. Для получения надёжных результатов операцию выполняют многократно, чтобы время превысило погрешность таймера.

Контейнер List<T> реализован как шаблонный класс двусвязного списка. Узел списка Node хранит значение типа T и два указателя – на предыдущий (prev) и следующий (next) узлы. Сам список хранит указатели на первый (head_) и последний (tail_) узлы и счётчик элементов size_. Хранение размера в отдельном поле позволяет получать его за O(1). Деструктор вызывает clear(), который обходит список и освобождает все узлы. Полный листинг класса приведён ниже.

Операции добавления и удаления на концах списка выполняются без обхода: достаточно перенаправить несколько указателей, поэтому их сложность O(1). Отдельно обработаны граничные случаи: добавление в пустой список (head_ и tail_ указывают на новый узел) и удаление последнего элемента (head_ и tail_ становятся nullptr). Полный листинг класса приведён ниже.

Операции insert и erase работают по индексу. Индекс проверяется на допустимый диапазон, при выходе за него выбрасывается std::out_of_range. Вставка и удаление на концах делегируются push_front/push_back и pop_front/pop_back (O(1)). Для остальных индексов выполняется последовательный проход от головы списка до нужной позиции, поэтому сложность O(n). Метод print() выводит содержимое списка и также имеет сложность O(n). Полный листинг класса приведён ниже.

**Файл `include/List.hpp`:**

```cpp
#pragma once // Защита от повторения
#include <iostream>
#include <stdexcept>

// Шаблонный класс двусвязного списка
template <typename T>
class List
{
private:
	struct Node
	{
		T data;
		Node *prev;
		Node *next;

		Node(const T &value) : data(value), prev(nullptr), next(nullptr) {}
	};

	Node *head_;
	Node *tail_;
	int size_;

public:
	//! Конструктор
	List() : head_(nullptr), tail_(nullptr), size_(0) {} /

	//! Деструктор
	~List()
	{
		clear();
	}

	//! Очистка списка
	void clear()
	{
		Node *current = head_;
		while (current != nullptr)
		{
			Node *next = current->next;
			delete current;
			current = next;
		}
		head_ = nullptr;
		tail_ = nullptr;
		size_ = 0;
	}

	//! Размер списка
	int size() const
	{
		return size_;
	}

	//! Добавление в начало
	void push_front(const T &value)
	{
		Node *newNode = new Node(value);
		if (head_ == nullptr)
		{
			head_ = tail_ = newNode;
		}
		else
		{
			newNode->next = head_;
			head_->prev = newNode;
			head_ = newNode;
		}
		size_++;
	}

	//! Добавление в конец
	void push_back(const T &value)
	{
		Node *newNode = new Node(value);
		if (tail_ == nullptr)
		{
			head_ = tail_ = newNode;
		}
		else
		{
			newNode->prev = tail_;
			tail_->next = newNode;
			tail_ = newNode;
		}
		size_++;
	}

	//! Удаление из начала
	void pop_front()
	{
		if (head_ == nullptr)
			return;

		Node *temp = head_;
		head_ = head_->next;
		if (head_ != nullptr)
		{
			head_->prev = nullptr;
		}
		else
		{
			tail_ = nullptr;
		}
		delete temp;
		size_--;
	}

	//! Удаление из конца
	void pop_back()
	{
		if (tail_ == nullptr)
			return;

		Node *temp = tail_;
		tail_ = tail_->prev;
		if (tail_ != nullptr)
		{
			tail_->next = nullptr;
		}
		else
		{
			head_ = nullptr;
		}
		delete temp;
		size_--;
	}

	//! Вставка по индексу
	void insert(int index, const T &value)
	{
		if (index < 0 || index > size_)
		{
			throw std::out_of_range("Индекс вне диапазона");
		}
		if (index == 0)
		{
			push_front(value);
			return;
		}
		if (index == size_)
		{
			push_back(value);
			return;
		}

		Node *current = head_;
		for (int i = 0; i < index - 1; ++i)
		{
			current = current->next;
		}

		Node *newNode = new Node(value);
		newNode->next = current->next;
		newNode->prev = current;
		current->next->prev = newNode;
		current->next = newNode;
		size_++;
	}

	//! Удаление по индексу
	void erase(int index)
	{
		if (index < 0 || index >= size_)
		{
			throw std::out_of_range("Индекс вне диапазона");
		}

		if (index == 0)
		{
			pop_front();
			return;
		}
		if (index == size_ - 1)
		{
			pop_back();
			return;
		}

		Node *current = head_;
		for (int i = 0; i < index; ++i)
		{
			current = current->next;
		}

		current->prev->next = current->next;
		current->next->prev = current->prev;
		delete current;
		size_--;
	}

	//! Вывод в консоль
	void print() const
	{
		Node *current = head_;
		std::cout << "[ ";
		while (current != nullptr)
		{
			std::cout << current->data << " ";
			current = current->next;
		}
		std::cout << "]\n";
	}
};
```

Функция main() проверяет работу шаблона с двумя типами данных: int и std::string. Для списка целых чисел последовательно выполняются push_back, push_front, insert, erase, pop_front и pop_back, для списка строк – push_front и push_back. Код и результат выполнения приведены ниже.

## Анализ сложности

Пусть `n` - текущее количество элементов списка.

| Операция               | Сложность | Обоснование                                                                               |
| :--------------------- | :-------- | :---------------------------------------------------------------------------------------- |
| `Конструктор`          | **O(1)**  | Инициализация двух указателей и счётчика                                                  |
| `clear() / деструктор` | **O(n)**  | Нужно освободить каждый из n узлов                                                        |
| `size()`               | **O(1)**  | Возвращается значение поля size_                                                          |
| `push_front()`         | **O(1)**  | Создание узла и перенаправление указателей головы                                         |
| `push_back()`          | **O(1)**  | Есть указатель tail_, обход не нужен                                                      |
| `pop_front()`          | **O(1)**  | Сдвиг head_ и удаление одного узла                                                        |
| `pop_back()`           | **O(1)**  | Благодаря prev сдвиг tail_ выполняется без обхода (в односвязном списке было бы O(n))     |
| `insert(index, value)` | **O(n)**  | O(1) на концах; в остальных случаях проход от головы на index−1 шагов – в худшем случае n |
| `erase(index)`         | **O(n)**  | O(1) на концах; в остальных случаях проход от головы на index шагов                       |
| `print()`              | **O(n)**  | Один проход по всем узлам                                                                 |

Пространственная сложность контейнера – O(n): на каждый элемент приходится один узел, т.е. значение и два указателя (для int на 64-разрядной платформе узел занимает 24 байта). Все операции, кроме clear() и print(), требуют O(1) дополнительной памяти.

## Ответы на контрольные вопросы

1. **Что такое О-нотация (Big O) и зачем она нужна?**
   Это математическая запись, описывающая асимптотический рост времени работы (или объёма памяти) алгоритма при увеличении размера входных данных; константы и младшие члены отбрасываются. Нужна для сравнения алгоритмов независимо от конкретного компьютера и языка и для прогноза поведения на больших данных.

2. **Какая сложность у доступа к элементу массива по индексу? Почему?**
   O(1). Адрес элемента вычисляется арифметически: `адрес начала + индекс · размер элемента`, поэтому время не зависит от размера массива.

3. **Какая сложность у бинарного поиска? Почему?**
   O(log n). На каждом шаге диапазон поиска сокращается вдвое, поэтому для массива из `n` элементов потребуется не более `log₂n` шагов (например, для миллиона элементов - около 20).

4. **Что означает сложность O(n log n)? Приведите пример алгоритма.**
   Время растёт как `n`, умноженное на `log n`: примерно `n` операций на каждом из `log n` уровней разбиения. Примеры: сортировка слиянием, быстрая сортировка в среднем случае, пирамидальная сортировка.

5. **Что такое амортизированный анализ? Приведите пример.**
   Это оценка средней стоимости операции по длинной серии вызовов, а не в худшем одиночном случае. Пример: `push` в стеке на основе динамического массива, который удваивает ёмкость при заполнении: редкое расширение стоит O(n), но, распределённое на все операции, даёт O(1) на одну вставку.

6. **Какая сложность у двух вложенных циклов по n итераций каждый?**
   O(n²), так как тело внутреннего цикла выполняется `n · n` раз.

7. **Какая сложность у рекурсивного вычисления чисел Фибоначчи?**
   Экспоненциальная. Каждый вызов порождает два новых, поэтому дерево вызовов растёт примерно как φⁿ (φ ≈ 1,618), что принято записывать верхней оценкой O(2ⁿ). Причина - многократное пересчитывание одних и тех же значений; с мемоизацией или циклом задача решается за O(n).

8. **Что такое шаблоны функций? Как их объявить и использовать?**
   Это механизм, позволяющий написать одну функцию для разных типов. Объявляется так: `template <typename T> T max(T a, T b) { return (a > b) ? a : b; }`. При вызове `max(3, 5)` или `max(2.5, 1.5)` компилятор сам выводит `T` и создаёт нужную версию функции.

9. **Что такое шаблоны классов? Как их объявить и использовать?**
   Это шаблон для генерации классов с параметризованными типами. Объявляется как `template <typename T> class RingBuffer { ... };`, а использование требует явного указания типа: `RingBuffer<int> rb(10);`, `RingBuffer<string> sb(5);`.

10. **В чём преимущество шаблонов перед перегрузкой функций?**
    При перегрузке нужно вручную писать отдельную функцию для каждого типа, при этом код дублируется. Шаблон пишется один раз и работает для любого подходящего типа, включая те, которые появятся позже. Генерация кода происходит на этапе компиляции, поэтому накладных расходов во время выполнения нет.

11. **Как указать, что шаблонный параметр - тип?**
    С помощью ключевых слов `typename` или `class` в списке параметров: `template <typename T>` или `template <class T>`. Для обычного шаблонного параметра-значения указывается его тип, например `template <typename T, int N>`.

12. **Можно ли создать шаблон с несколькими параметрами типов?**
    Да. Параметры перечисляются через запятую: `template <typename T1, typename T2> class Pair { ... };`, использование: `Pair<int, string> p(1, "a");`. Так устроены, например, `std::pair` и `std::map`.

13. **Как провести экспериментальное измерение времени выполнения?**
    Взять момент времени до и после выполнения кода с помощью `std::chrono::high_resolution_clock::now()`, вычесть и привести разность к нужным единицам через `duration_cast` (например, к микросекундам). В работе это оформлено шаблонной функцией `measureTime`, принимающей лямбду. Для надёжности нужно собирать программу с оптимизацией и не давать компилятору выбросить измеряемый код (в работе для этого используется `volatile`-переменная `sink`).

14. **Почему при измерении времени нужно выполнять операцию многократно?**
    Одна быстрая операция выполняется за доли микросекунды, что сравнимо с разрешением таймера и погрешностью, поэтому результат будет ненадёжным. Многократное повторение и усреднение сглаживают влияние кэша, планировщика ОС и случайных помех, а суммарное время становится достаточным для точного измерения.

15. **Что важнее: сложность алгоритма или константа?**
    Для больших входных данных решающую роль играет сложность: алгоритм O(n log n) рано или поздно обгонит O(n²) при любой константе. Но для малых `n` и при одинаковой сложности именно константа определяет реальную скорость. Это видно и в нашем эксперименте: `RingBuffer` и `std::deque` оба выполняют операции за O(1), однако на очередных операциях STL быстрее в 2,3-2,7 раза за счёт меньших накладных расходов.
